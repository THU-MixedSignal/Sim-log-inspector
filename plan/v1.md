## Scope and ownership
New independent Git repository E:/spectre-log-inspector. All edits here only.
ADC repository, remote simulator jobs, source logs and models read-only. No OA.
No initial dirty files; no commit/push requested. No changes to existing workflow.

Goal: Spectre original evidence extraction and completion/integrity checks,
CLI/JSON for agents and localhost live dashboard for people. Five categories:
execution, diagnostics, settings_progress, testbench, data_resources. No causal
analysis, no inferred ADC correctness, no spectral analysis.

## Architecture
1. Versioned parser extracts source-located events, contexts, actual/requested
   settings, suppression and native footer. Unknown message codes retained.
2. Incremental binary reader -> SQLite event store, bounded block/line memory,
   persistent cursor; complete lines only while following. Changed/truncated
   files become a new generation. Events remain available by generation.
3. Read-only integrity adapter joins explicitly configured state/logStatus/raw
   metadata. raw mode is bounded PSF ASCII head/tail, not full waveform validation.
4. CLI scan/watch/status/events/report and read-only HTTP API. Browser polls
   paginated SQLite results, no full log reload. localhost only; no arbitrary
   filesystem browsing, write endpoint, process control, or shell execution.

## Input contract
Run manifest supplies run ID, spectre.out path and optional managed state,
logStatus, ASCII raw path, expected analysis and stop time. Paths resolve relative
to manifest. Existing managed artifacts are consumed without modifying them.
Network sources may be mounted or copied; no built-in SSH credentials or remote
launcher in v1. Collector may run alongside simulations using mounted paths.

## Delivery and verification
- Implement parser/store/integrity, CLI and standalone dashboard.
- Sanitized real fixtures from 8 local collected logs; hashes and golden expected
  codes/counts/terminal/settings reviewed independently of parser execution.
- Tests: real logs, chunk boundaries, restart/idempotence, truncation/rotation,
  effective/default units, suppression, fatal+exit0, analysis PASS/FAIL,
  incomplete raw, hostile UI text, API filtering and resource limits.
- Provide README, schema, operator instructions, support matrix, run manifests,
  deterministic tests and private local live demonstration.
- Do not claim exhaustive vendor-version coverage or full raw validation.

## Runtime management
Data plane is append-only events with SQLite WAL, single writer; HTTP read-only
connections. Separate watch/serve processes; no scheduler/service installation.
Ctrl-C clean shutdown. Output/runtime isolated under .runtime, retained until
explicit cleanup. Watch idle interval configurable, bounded work each tick.
Tests and measurements must accompany performance claims.
