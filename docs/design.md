# 设计方案（v0.4）

## 目标
在仿真进行中尽早让执行 Agent 和人看到已经出现的问题证据，避免无效仿真占用时间。衡量标准是发现延迟（问题行写进 spectre.out 到被告知）和召回（早期信号是否被抓到）。执行 Agent 是主要读者：输出要小，不能塞满它的上下文，并且每条结论都能一步定位到原文。部署独立，不侵入仿真流程，不停止仿真。

## 分层与所有权

```text
只读 manifest -> spectre.out + 可选 state/logStatus/raw 头尾
                        |
           collector（run/watch）：增量读取、游标、心跳
                        |
           parser：头行块、原生消息、notice、抑制、设置、测试台记录
                        |
         SQLite WAL（单写者）+ integrity 有界检查
                 /                    \
     CLI 文本/JSON、wait          只读 HTTP（同一份 JSON）-> 页面
```

parser 不访问文件系统；store 不作电路推断，输出构造也在 store 里（CLI 和 HTTP 共用）；render 只把同一份数据排成文本；server 只读打开数据库。

## 采集
`run` 先绑定端口再采集，前台采集加页面；`watch`、`serve` 可分开运行。每轮每个运行最多 2 MiB、单行 64 KiB；落后时连续处理，追平后按间隔轮询。每个运行独立 try：一个运行的异常只记录在该运行上，不挡住其他运行。每轮写心跳，正常退出时删除。源文件替换、截断或出现新的启动段时开新代次，旧证据保留。游标记下当前文件内容从哪一代开始读（`file_generation`）：取旧代次证据时据此区分“同一文件里先前的尝试”（path:line 仍有效）和“文件已被替换”（path:line 指向旧内容，raw 是入库时的原文）。未写完的最后一行不入库，只读出其中的进度条格数：Spectre 会在这一行上持续追加进度点，可能长达数小时。数据库是派生索引：schema 不符时拒绝打开，旧库不动；游标里缺少后来新增的解析状态键时，按默认值补齐。

## 解析
Spectre 用“头行 + 缩进块”打印消息。头行（`Warning|Notice|Error|Fatal error from/found by spectre [at time = …]`）开启一个块；块内带标签的行（`WARNING (CODE):`）是一条消息，块内第一行无标签正文是一条 notice（级别取头行），其后的缩进行是续行；`Further occurrences … suppressed` 记在上一条消息上，`N warnings/notices suppressed` 是原生全局汇总。消息的仿真时间只取本块头行。瞬态结束时间取自 `Transient Analysis … (0 s -> stop)`。未知编号保留；无编号消息按正文（数字掩码）归组。

带编号的标签行在任何位置都是原生消息；不带编号的标签行只有缩进在头行块内才算（22 份仓库真实日志和 210 份本机非瞬态原生日志中，块外没有出现过未编号标签）。块外行首的 `ERROR:`、`FATAL:` 等是测试台之类的其他输出：保留原文和行号，归为 `TB:reported_<原词>`，不计为 Spectre 错误。

每个分析由一行横幅开始：`Transient|DC|AC|Monte Carlo … Analysis `名称'`，其后可带扫描范围。头行的 `during … analysis `名称'` 子句取第一个（最内层）。问题组的阶段就是所在分析，读入阶段为 setup。DC/AC 头行给的是扫描点（`at vcm = …`、`at iteration = …`），不是时间；DC/AC 中的 `Accumulated DC solution time = 0 s` 等求解时间统计也不计入仿真时间。

进度条有 70 格，每 6 个点后跟一个数字。Spectre 每次换行后从行首重打到当前进度，后面常接测试台输出。解析时只接受与标准进度条逐字一致的前缀（`10. Try …`、缩进的 `.probe` 都不算），取当前分析内最长的一次，遇到新横幅归零。在仓库的 noise 原生运行中，进度条最多比测试台报告的帧时间领先 0.76 个百分点（不到 1 格），所以它只是 Spectre 自己的进度显示，不能当作时间下限。R4MEAS 能解析出的记录才计为帧；无法解析的记录、原始 PASS/FAIL 和块外未编号标签都算其他测试台行。

## 完整性
ERROR/FATAL、managed 终止或限额、logStatus 最新状态 FAIL 判失败；正常结尾行只证明原生日志正常结束；raw 只做 PSF ASCII 头尾检查。没有结尾也没有可信状态时为 unknown。

## 早发现
- 关注原因都是事实：失败、命中用户规则、未结束且日志超过阈值未修改、采集出错、日志读取失败。
- 规则由用户写在 manifest 里，工具只报告命中；参考运行对比列出参考中没有出现过的键。
- 每组记录首条消息的仿真时间、占结束时间的比例、首次被采集的时刻。
- 进度有两种来源：日志最近给出的仿真时间（下限）；Spectre 进度条比它靠前时也一并给出。日志在两条消息之间可能几个小时没有时间行，这时仍能从进度条看到进展。
- `wait` 在新问题组、状态变化、规则命中、日志超时、采集出错、采集器离线时返回；页面在同样的变化上发浏览器通知。

## Agent 输出
- 默认是文本，每行一个事实，字段顺序固定；`--json` 是同一份内容，缺省键表示 false、无或 0。
- 渐进获取：`status`（每个运行一行，需要关注的再加几行）→ `show RUN`（问题组）→ `evidence eNNN`（原文与 path:line）。句柄和游标都能原样传回下一条命令；被截断的列表给出继续的命令。
- 有界：status 每个运行最多 2 个错误、每条规则 5 个键；show 默认 30 组且隐藏未命中规则的 NOTICE；evidence 最多 20 行续行、单行 400 字；wait 最多 20 条变化；measurements 默认 20 条。
- `wait` 只返回变化和下一个 cursor，不附带运行摘要；新问题组命中规则时合成一条。
- 时间用 Spectre 日志自己的写法（ns、us），便于对照原文。

## 页面
固定英文与白色主题。采集状态只出现一次；Failed、Unknown、Incomplete evidence 明确保留。页头只留运行名、状态与弱化的日志时间，进度放到时间轴附近（进度条读数靠前时加一个 `Meter N%`，时间轴填充取两者中靠前的一个）；不重复问题计数或规则名单。按用户原图保留紧凑横排：级别、编号、次数、首次时间/百分比、tag、正文。编号 14px 加粗、正文 15px 深色，次数和时间 12px 灰色；红色 Rule、琥珀色参考、蓝色 New 保留描边，单次打印不重复显示 ×1。展开只保留 First/Last、12px 灰色来源位置和原文框，不增加字段卡片或重复标签。级别、规则名、参考运行和抑制范围通过原文及悬停提示保留。700px 以下自动换行。测量入口用轻量文字按钮，窄屏使用原生运行选择器。颜色只表示“请看这里”，正常结束的运行不着色；级别同时用形状（■▲●◆）表示。页面就地更新，键盘焦点和展开状态保持；日志文本只用 textContent 写入；CSP 只允许同源脚本和样式。

左侧关闭状态只存当前浏览器 localStorage，并按运行 ID/代次匹配；保留采集与证据，
新代次自动重新显示。Save/Close 是选择按钮的同级控件，保留键盘焦点；全部关闭后
仍可 Restore closed。只读另存提供 HTML 静态报告和 JSON 当前代次全部已入库事件。
导出在事务内完成摘要/事件读取，分块写临时文件，保留源证据与摘要边界；源日志
和波形文件不嵌入报告。

## 演进
更多真实 Spectre 版本语料，独立 ADC 契约插件，managed analysis-only 波形检查，有真实语料后再支持其他仿真器。新分类与判断必须带正反回归样例。不会扩展到因果诊断、杂散分析、自动停止或修改仿真。
